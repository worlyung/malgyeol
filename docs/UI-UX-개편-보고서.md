# 회의 받아쓰기 UI·UX 개편

검토·적용일: 2026-10-27

## 적용 범위

실행 앱의 받아쓰기, 기록·요약, 용어집, 설정 4개 화면과 각 화면의 재생기·검색·내보내기·입력·확인 창, 화면 영역 지정, AI 연결 안내 페이지를 분석하고 개편했다. 음성인식·화자 추론·AI 호출을 처리하는 Python 코드는 변경하지 않았다. 설치·제거 프로그램과 배포용 소개 문서는 실행 앱 화면에 포함하지 않았다.

## 분석과 반영

| 영역 | 확인한 문제 | 반영 내용 |
|---|---|---|

| 화면 감시 | 감시가 꺼졌을 때 빈 미리보기의 의미가 불분명함 | 감시 전 안내, 공통 스타일의 영역 선택 창, 오류 시 적용 방지·닫기 |
| 문장 수정 | 영역 밖을 누르면 자동 저장되어 저장·취소 의도가 불분명함 | 별도 문장 수정 창, 명시적인 저장·취소, 빈 내용 방지, 저장 실패 시 원문 유지 |

| 설정 | 일반 설정·전문 인식 옵션·인물 관리가 한 화면에 모두 나열됨 | ‘AI 연결 / 음성인식 / 화자·교정 / 등록된 사람’ 분류, 저장 중·저장 완료·실패·입력 범위 표시 |

## 변경 파일

- `web/index.html`: 전체 화면 배치와 입력·내보내기·설정·안내 창 구조.
- `web/style.css`: 전체 디자인 체계와 창 크기별 배치.
- `web/app.js`: 기존 기능에 연결된 편집·목록·입력 상태·오류 처리.
- `web/workspace.js`: 탐색·공통 대화상자·빈 화면·접근성 동작.
- `web/api-key-guide.html`: AI 연결 안내의 디자인과 안내 경로.

기존 4개 웹 파일은 `docs/ui-backup/`에 보관했다. 원래 `data/`의 설정·회의·명부·음성 파일은 수정하지 않았다. 이 폴더는 Git 저장소가 아니므로 커밋·원격 반영은 하지 않았다.

## 검증 결과

### 실제 화면과 로컬 API

`tests/ui_smoke.js`의 45개 검사 통과. 시험용 서버는 `127.0.0.1:8876`, 데이터는 `%TEMP%/livecaption-ui-review-20261027`에 분리했다.

- 4개 화면과 도구·설정 분류, 안내 창, 검색 결과와 빈 상태.
- 문장 수정의 실제 저장, 취소, 의도적으로 실패시킨 저장 요청의 원문 보존.
- 회의 정보·폴더·용어·교정 규칙·인물 등록·설정의 실제 로컬 API 저장.
- 시험용 무음 WAV의 재생과 속도 변경.
- Word 내려받기 성공, TXT·SRT·MD·JSON·요약 MD·요약 DOCX의 응답 확인.
- 요약 펼치기·크게 보기, 키보드 검색·닫기·초점 복원.
- 1440×1000, 1280×800, 900×640, 390×844에서 4개 주 화면의 가로 잘림 확인.
- 파일 입력 화면·음성인식 설정·용어집의 입력칸 폭을 추가 검사하고, 발견된 용어집 입력 폭 문제를 수정.
- 실행 중 JavaScript 예외 없음. 오류 복구 시험에서 발생한 HTTP 500은 의도적으로 넣은 시험 응답이다.

### 통제된 상태 응답

`tests/ui_states.js`의 12개 검사 통과. 실제 녹음을 실행하는 대신 시작·중지 API 응답과 인식 이벤트를 주어 다음 화면 동작을 확인했다.

- 실행 중 입력 잠금, 실시간 문장 추가, 첫 문장 후 빈 안내 제거, 인식 중 자막.
- 중지 후 기록 화면 이동, 마무리 중 요약 잠금, 완료 후 요약·새 회의 시작 가능.
- 잘못된 설정 저장 방지와 올바른 값 입력 후 복구.
- 화면 캡처 오류 안내와 적용 방지, Escape로 창 닫기.

총 **57개 UI 검사 통과**. 세부 항목은 `ui-test-results.json`에 저장했다.

### 소스와 기존 테스트

- `node --check web/app.js`, `node --check web/workspace.js`: 통과.
- 별도의 프런트엔드 빌드 단계가 없는 HTML/CSS/JavaScript 앱이며, 로컬 서버가 변경 파일을 직접 제공한다.
- 기존 Python 테스트 10개 중 9개 통과, 1개 실패.
- 실패 항목: `test_cli_ai.CliAiTests.test_codex_receives_prompt_and_returns_answer`. 테스트는 `지침\n\n질문`만 전달되기를 기대하지만 기존 `app/cli_ai.py`는 회의록에 사용자 호칭·말투가 섞이지 않도록 추가 지침을 붙인다. 해당 Python 구현과 테스트는 이번 작업에서 변경하지 않았다.

## 검증하지 않은 범위

실제 마이크·PC 소리의 장시간 음성인식, 실제 얼굴·목소리 판별 정확도, 외부 AI 요약·자료 추출 호출, Windows 설치·제거·독립 WebView2 창은 이번 브라우저 UI 검증 범위에 포함하지 않았다. AI 호출 비용은 발생시키지 않았다. 브라우저 화면 검증 통과를 이 기능들의 정확도 검증으로 해석하면 안 된다.

## 사용 방법

기존 `회의 받아쓰기 시작.bat`로 프로그램을 다시 열면 새 화면을 사용한다. 이미 열린 브라우저에서는 새로고침한다.

1. 왼쪽 **받아쓰기** → 회의 제목·소리 선택 → **받아쓰기 시작**.
2. 오른쪽 도구에서 자료 준비, 발언자 확인, 메모·키워드를 필요에 따라 사용.
3. **마치고 저장** → **기록·요약**에서 문장을 눌러 듣고 **수정**.
4. **내보내기**에서 문서 형식 선택. AI 기능은 **설정 → AI 연결**에서 확인.

시험 재현 자료 생성: `python/python.exe scripts/ui_review_fixture.py`. 시험 서버에는 반드시 `LT_DATA_DIR`을 위 TEMP 경로로 지정한다. 브라우저 검사는 Playwright `browser_run_code_unsafe`의 `filename`으로 `tests/ui_smoke.js`, `tests/ui_states.js`를 실행한다. 시험은 위 전용 서버를 대상으로만 수행한다.
