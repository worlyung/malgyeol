# 공개 배포할 때 확인할 것 — 오픈소스 라이선스 점검

결론부터: **오픈소스 때문에 공개 배포가 막히는 것은 없습니다.** 다만 세 가지를 지켜야 합니다.

1. LGPL 부품(FFmpeg, libsoxr)의 **라이선스 전문과 출처를 함께 배포**할 것
2. 프로그램 안에 **'사용한 오픈소스' 안내를 넣을 것** (이 문서를 함께 배포하면 충족)
3. 아래 3장의 개인정보·생체정보가 섞여 나가지 않게 할 것 — **이쪽이 더 중요합니다**

## 2. 조건이 붙는 것 (LGPL / MPL) — 지금 방식이면 문제없음

| 부품 | 라이선스 | 왜 괜찮은가 |
|---|---|---|
| **FFmpeg** (PyAV가 안고 있음) | LGPL 2.1+ | 별도 DLL로 들어 있어 사용자가 교체할 수 있습니다. 라이선스 전문만 함께 배포하면 됩니다. |
| **libsoxr** (python-soxr) | LGPL 2.1+ | 위와 같음. 별도 `.pyd` 파일입니다. |
| certifi, tqdm | MPL 2.0 | 고치지 않고 그대로 배포하면 조건 없음 |
| **PyInstaller** | GPL 2.0 **+ 예외조항** | 예외조항 덕분에 *PyInstaller로 만든 프로그램*은 GPL이 되지 않습니다. 널리 쓰이는 방식입니다. |

LGPL에서 금지되는 것은 "사용자가 그 라이브러리를 바꿔 끼울 수 없게 통째로 굳혀 배포"하는 것인데,
이 프로그램은 파이썬 + 개별 DLL 구조라 해당하지 않습니다.

> 피하고 싶다면: `soxr`는 PyAV의 리샘플러로 대체할 수 있지만, FFmpeg 자체가 LGPL이라
> 어차피 같은 조건이 남습니다. **지금 구조를 유지하고 고지만 하는 편이 낫습니다.**

## 3. 개인정보·기관 정보 (공개판에서 정리한 것)

### 가. 얼굴·목소리 정보 (생체정보)
`data/faces/` 에 쌓이는 **얼굴 특징값과 성문**은 생체정보에 해당할 수 있습니다.
저장소와 공개 설치 파일에는 들어 있지 않습니다. 직접 빌드할 때도 `--with-members` 옵션은 쓰지 마세요.

### 나. 명부·용어사전
공개판의 명부(`data/members.json`)는 비어 있고, 용어사전은 사람 이름과 특정 기관명이 없는
**일반 의회 용어**만 담았습니다. 각 기관에서 의원 이름 등을 넣은 뒤에는 그 파일을 다시 공개하지 않도록 주의하세요.

### 다. 회의 녹취 파일
`data/sessions/` 에는 실제 회의 음성과 녹취록이 들어갑니다. 저장소에 올리지 않으며,
빌드 스크립트도 빈 폴더만 넣습니다.

### 라. 아이콘
프로그램 아이콘(마이크 그림)은 이 프로젝트에서 직접 만든 것으로, 기관 상징(CI)이 아닙니다.
