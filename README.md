# 말결 (MALGYEOL) · 1.00

**대화를 기록으로 잇다.**

## 말결 1.00 다운로드

[GitHub Releases](https://github.com/worlyung/malgyeol/releases/latest)에서 `Malgyeol-1.00-Setup.exe`를 받습니다.
Windows 11용이며 Python과 음성인식 모델이 포함되어 있습니다. 설치 후 말결 바로가기로 실행합니다.
개인 명부, 용어집, 녹음, 얼굴·목소리 특징과 API 키는 배포본에 포함하지 않습니다.

이 프로젝트는 충청남도 박소영님의 LiveCaption(MIT)을 바탕으로 이름·화면·사용 흐름을 개편한 버전입니다.
원저작권 표시는 [LICENSE](LICENSE)에 보존했습니다.
말결 업데이트는 GitHub Releases의 `latest.json`을 확인합니다. 아래의 이전 GitLab 배포 설명은 원본 프로젝트 참고용입니다.

PC에서 나는 소리를 실시간으로 받아 적고, 누가 말했는지 구분해 녹취록을 만드는 프로그램입니다.
도의회 본회의·상임위 중계처럼 **화면에 발언자 얼굴이 나오는 회의**에 맞춰 만들었습니다.

- 음성인식, 얼굴 인식, 목소리 대조는 이 PC에서 돌아갑니다. 인터넷으로 음성을 보내지 않습니다.
- 요약은 로그인된 Claude Code(없으면 Codex)를 기본으로 사용합니다. 규칙으로 못 찾은 화자 지명은 로그인된 Codex(없으면 Claude Code)에 해당 문장과 최근 문장을 보냅니다. 기존 API 키 방식도 설정에서 선택할 수 있습니다.

```
┌ 소리 입력 ─────────┐   ┌ 인식 ────────────┐   ┌ 녹취록 ──────────────┐
│ PC 소리(루프백)     │   │ Whisper          │   │ [00:12:31] 김민준 의원 │
│ 마이크             │─▶│ + 직전 문장 힌트  │─▶│  에너지 저장과 효율화를 │
│ 영상 파일 / 주소    │   │ + 자모 사후교정   │   │  ... (클릭하면 재생)   │
└──────────────────┘   └─────────────────┘   └────────────────────┘
                              ▲                        ▲
                     화면 얼굴 인식 ─────────── 목소리(성문) 대조
```

## 1. 설치와 실행

### 1-1. 설치 파일로 (권장)

GitLab 저장소의 **Releases** 에서 설치 파일을 받아 두 번 누르면 됩니다. 파이썬을 따로 깔 필요도, 관리자 권한도 없습니다.

| 설치 파일 | 크기 | 설명 |
|---|---|---|
| `말결_설치_경량.exe` | 약 175MB | 설치 중에 GitLab 에서 음성인식 모델(약 0.9GB)을 받습니다. 설치할 PC가 `gitlab.aigov.go.kr` 에 접속할 수 있어야 합니다. |
| `말결_설치.exe` | 약 0.93GB | 모델까지 들어 있어 인터넷 없이 설치합니다. |

두 파일 모두 프로그램 기능은 같고, 어느 의회에서나 쓰는 **일반 의회 용어사전**이 들어 있습니다.
명부(의원 이름·직함)는 비어 있으니 각 기관에서 등록해 쓰세요.
얼굴 특징·목소리 성문·설정(API 키)·회의 기록은 들어 있지 않아, 새 PC에서는 처음 상태로 시작합니다.

1. 설치 창에서 설치할 곳을 고르고 [설치하기] (기본 위치: 사용자 폴더의 `LiveCaption`, 영문 경로 권장)
2. 다 풀면 바탕화면과 시작 메뉴에 **`말결`** 바로가기를 만듭니다.
3. 끝나면 창이 앞으로 나오며 **"설치가 완료되었습니다. 바로 프로그램을 실행할까요?"** 라고 묻습니다.

서명되지 않은 exe라 처음 실행할 때 Windows가 'PC 보호' 창을 띄울 수 있습니다. **추가 정보 → 실행**을 누르면 됩니다.

### 1-2. 폴더에서 바로 (시작 파일)

저장소 폴더를 받았다면 **`말결 시작.bat`** 을 두 번 누르세요.

- **처음 한 번** (10~30분, 인터넷 필요): 필요한 것을 모두 이 폴더 안에 받아 설치하고,
  **바탕화면에 `말결` 아이콘**을 만든 뒤 프로그램 창을 엽니다. 진행 상황이 한글로 나옵니다.
  1. 파이썬 — python.org 공식 '설치 불필요판'을 이 폴더의 `python\` 에만 풉니다 (PC에 설치되지 않음)
  2. 꾸러미 (약 800MB)
  3. 음성인식·얼굴·화자 모델 (약 1.6GB를 받아, 가볍게 다시 저장해 0.9GB만 남깁니다)
  중간에 끊기면 다시 누르세요. 받은 것은 다시 받지 않고 이어서 합니다.
- **다음부터**: 바탕화면 아이콘(또는 같은 파일)을 누르면 곧바로 프로그램 창이 열립니다.

기관망 보안 장비가 있어도 Windows 인증서를 믿도록 되어 있습니다. 설치가 안 되면 `data\설치기록.txt` 를 확인하세요.

**인터넷이 없는 PC**: 인터넷 되는 PC에서 `python -m scripts.build_package --zip --with-roster` 으로 모두 담은 꾸러미를 만들어
옮긴 뒤, 압축을 풀고 같은 `말결 시작.bat` 을 누르면 설치 없이 바로 열립니다.
`--with-roster` 는 명부(이름·직함)만 담고 얼굴·성문은 담지 않습니다. 얼굴·성문까지 담는 `--with-members` 는 내부용입니다.

### 1-3. 개발할 때

`.venv` 가 있으면 시작 파일이 그것으로 엽니다.

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m scripts.download_models
.venv\Scripts\python.exe -m app.gui      # 창으로 열기 (app.main 은 브라우저로)
```

서버는 이 PC 안에서만 돕니다(127.0.0.1). 바깥에서는 접속할 수 없습니다.

## 2. 쓰는 법

### 2-1. 소리 가져오는 세 가지 방법

| 방법 | 언제 쓰나 | 설명 |
|---|---|---|
| **PC 소리(스피커)** | 중계를 보면서 실시간 녹취 | 브라우저에서 의회 중계를 틀어두면 그 소리를 그대로 받아 적습니다. **스피커 볼륨을 0으로 하거나 음소거해도 받아 적으므로**, 이어폰이 없어도 사무실에서 소리를 내지 않고 쓸 수 있습니다. 들으려면 볼륨을 올리면 됩니다. 장치를 고를 필요가 없습니다. |
| **마이크** | 현장에서 직접 녹음 | 회의실에서 노트북 마이크로 녹음할 때. 장치 칸에서 마이크를 고릅니다. |
| **저장된 파일 / 영상 주소** | 지난 회의 녹취 | mp4·mp3·wav 파일을 고르거나, 영상 주소를 붙여 넣습니다. 실시간보다 빠르게 처리합니다. 소리 장치가 필요 없습니다. |

**PC 소리는 스피커 볼륨과 상관없이 받습니다.** Windows 10 2004(2020년) 이후에 들어 있는 '프로세스 루프백' 기능으로
이 프로그램을 뺀 PC의 모든 소리를, 스피커 볼륨·음소거를 적용하기 **전에** 받습니다.
- 가상 오디오 드라이버(VB-CABLE 등)·외부 소프트웨어·관리자 권한이 필요 없습니다. 그 기능을 부르는 작은 도구
  (`scripts/proc_capture.cs`)를 처음 쓸 때 Windows 에 기본으로 있는 C# 컴파일러로 만들어 `data/bin/` 에 둡니다.
  직접 작성한 코드라 따로 라이선스 문제가 없습니다.
- PC의 모든 소리를 받으므로, 받아쓰는 동안 다른 동영상을 틀면 그 소리도 함께 받아 적습니다.
- 중계 화면·브라우저 탭 자체를 음소거하면 그 프로그램이 소리를 내지 않아 받아 적지 못합니다.
- 이 기능을 쓸 수 없는 PC(옛 Windows 등)는 예전 방식(기본 출력 장치 루프백)으로 받습니다. 이때는 볼륨을 0으로 하면
  받아 적지 못하지만, 낮게(예: 3~5%) 해 두면 작게 들어온 소리를 자동으로 키워 받아 적습니다.
- **소리 출력 장치가 하나도 없는 PC**(스피커·이어폰·모니터 소리 모두 없음)는 브라우저가 소리를 낼 곳이 없어 받을 수 없습니다.
  이때는 "이 PC에는 소리 출력 장치가 없어 PC 소리를 받을 수 없습니다. 스피커나 이어폰을 연결해주세요." 라고 알립니다.
  (이어폰을 꽂아만 두어도 되고, 녹화된 회의는 '저장된 파일 / 영상 주소'로 받아 적을 수 있습니다)

충청남도의회 영상은 주소를 그대로 넣을 수 있습니다.
회의 영상 페이지에서 F12 → 네트워크 탭을 보면 `.../attach/video/bon/13/371_bon_260901_1cha.mp4` 같은 주소가 보입니다.
"시작(초)"에 숫자를 넣으면 그 지점부터 받아씁니다.

### 2-2. 받아쓰기 탭 — 성능

| 항목 | 설명 |
|---|---|
| 성능 | 보통(PC 속도에 맞춰 미리보기, 권장) / 절전(CPU 최소, 미리보기 없음) |

**바꾸는 즉시 저장되고, 받아쓰는 중에도 성능 설정은 바로 적용됩니다.** 설정 탭에서 평소 쓰는 CTranslate2 Whisper 모델 폴더를 지정할 수 있습니다. 모델을 열지 못하면 기본 large-v3-turbo를 사용합니다. 모델 변경은 다음 회의부터 적용됩니다.

### 2-3. 화면 보기

- 확정된 문장은 목록에 쌓이고, **아직 확정되지 않은 말은 목록 바로 아래 칸에 자막처럼** 흘러갑니다.
  (초록 점이 깜빡이면 지금 듣고 있다는 뜻입니다. 절전 모드에서는 미리보기가 없다고 안내가 뜹니다)
- **화자마다 이름표 색이 다릅니다.** 같은 이름이면 항상 같은 색이라 누가 언제 말했는지 한눈에 보입니다.
  이름 옆 작은 꼬리표는 어떻게 알아냈는지 알려 줍니다 — 얼굴, 목소리, 맥락, 직접(직접 지정).
- **중지를 누르면 기록·요약 탭으로 자동으로 넘어갑니다.** (마무리에 10초쯤 걸립니다)
  '저장된 파일 / 영상 주소'는 끝까지 받아 적으면 저절로 마무리되고 기록·요약 탭으로 넘어갑니다.
  마지막 문장을 정리하는 동안(마무리 중)에는 그 회의를 지우거나 AI 요약할 수 없습니다. 끝난 뒤 해 주세요.
  느린 PC는 마무리가 길어질 수 있으며, 작업이 끝날 때까지 기다립니다(최대 10분, 넘으면 오류로 표시하고 마칩니다).
- **회의 제목은 받아쓰는 중에도 바꿀 수 있습니다.** 바꾼 제목이 기록·요약 탭과 내보내기 파일 이름에 그대로 쓰입니다.
- **문장을 클릭하면 그 대목의 소리가 재생됩니다.** (받아쓰기 검수용)
- "수정"으로 글자를, "화자"로 발언자를 고칠 수 있습니다. 화자를 바꾸면 **누르는 즉시** 녹취록에 반영되고,
  같은 목소리의 다른 문장은 뒤에서 찾아 잠시 뒤(수십 초) 함께 바뀝니다. 이름 뒤에 `모두`를 붙이면
  (예: `김민준 의원 모두`) 같은 화자로 잡힌 문장을 한꺼번에 바꿉니다.
- **녹취록 검색** — 받아쓰기 탭과 기록·요약 탭 모두 내보내기 단추 왼쪽에 검색 칸이 있습니다.
  찾은 글자는 노란색, 지금 보는 결과는 주황색으로 칠해지고 `3/17` 처럼 몇 번째인지 보입니다.
  **Enter**(또는 ▼)로 다음, **Shift+Enter**(또는 ▲)로 이전, **Esc** 로 지우기, **Ctrl+F** 로 검색 칸으로 갑니다.
  받아쓰는 중에 새 문장이 들어오면 저절로 다시 찾습니다.
- **관심 키워드** — 받아쓰기 탭 오른쪽에 담당 사업명·소속 부서명을 넣어 두면, 발언에 나올 때 Windows 알림(창이 가려져
  있어도)으로 알리고 녹취록에 형광펜으로 표시합니다. 띄어쓰기가 달라도 찾으며, 같은 키워드는 30초에 한 번만 알립니다.
  녹음에 섞이지 않도록 소리는 내지 않습니다. 언급 목록을 누르면 그 문장으로 이동합니다.
  넣어 둔 키워드는 설정에 저장되어 프로그램을 껐다 켜도 남습니다.
- **성능 모드**는 받아쓰는 도중에 바꿔도 다음 인식부터 바로 적용됩니다.
- **TXT / DOCX / SRT / JSON** 으로 내보냅니다. 받는 파일 이름은 회의 제목입니다
  (파일 이름에 쓸 수 없는 `\ / : * ? " < > |` 는 `_` 로 바꿉니다). 누르면 저장할 곳을 묻는 창이 뜹니다.

### 2-4. 용어집 — 인식률 올리기

기관에서 쓰는 오인식 사전(CSV)이 있으면 그대로 넣으면 됩니다.
머리글이 `오인식표현, 표준용어, 분류, 세부분류` 인 파일이면 됩니다.

```bash
.venv\Scripts\python.exe -m scripts.import_glossary "C:\경로\오인식사전.csv"
```

한 줄이 '바꾸기 규칙'이 되고, 표준용어는 '용어 목록'에도 들어갑니다.

화면의 **용어집 탭**은 세 가지만 합니다.
1. **용어 한 번에 넣기** — 이름·용어를 쉼표나 줄바꿈으로 붙여 넣고 분류를 골라 추가
2. **바꾸기 규칙 넣기** — '찾을 말(잘못 인식되는 표현)'과 '바꿀 말(바른 표기)'을 적고 추가하면 바로 저장
   (같은 '찾을 말'이 이미 있으면 '바꿀 말'만 새것으로 바꿈)
3. **등록된 용어 및 바꾸기 규칙 보기** — 수가 많아 화면에 늘어놓지 않고, [보기]를 누르면 분류별 용어와
   바꾸기 규칙 전체를 정리한 텍스트 파일이 새 창에서 열림.
   **찾아서 고치기·지우기** 칸에 낱말을 넣으면 그 낱말이 든 규칙·용어가 (최대 30개) 나오고,
   규칙은 '찾을 말'·'바꿀 말'을 고쳐 [저장]하거나 [삭제], 용어는 [삭제]할 수 있음(바로 저장)

공개판에 들어 있는 용어사전은 어느 의회에서나 쓰는 일반 의회 용어 **176개 규칙 / 177개 용어**입니다.
사람 이름과 특정 기관의 기관명·사업명은 넣지 않았으니, 기관의 의원·간부 이름과 자주 나오는 명칭을 직접 추가하세요.

의원 이름이나 의회 용어처럼 Whisper가 잘 틀리는 말을 넣어 둡니다. 받아 적은 문장을 **확정한 뒤 고치는 데** 씁니다.
용어 수에 제한은 없지만, 용어의 길이에 따라 쓰이는 방식이 다릅니다.

1. **바꾸기 규칙** — 자주 틀리는 표기를 그대로 바꿉니다. 모든 규칙이 적용됩니다. (예: "예산결산특위원회 → 예산결산특별위원회")
2. **자모 단위 사후 교정** — 인식 결과에서 **20자 이하** 용어와 비슷한 낱말을 찾아 고칩니다.
   "홍길둥 → 홍길동" 같은 한 글자 차이를 잡아냅니다. (설정 탭 → 용어집 적용 → '비슷한 말 자동 교정', '교정 민감도')
3. **20자를 넘는 긴 정식명칭**(예: "○○○ 지원에 관한 조례 일부개정조례안")은
   비슷한 말 찾기 후보에서 빠집니다. 바르게 받아 적힌 문장이 다른 말로 잘못 고쳐지지 않게 지켜 주는 역할만 합니다.
   틀리게 인식되는 일이 잦은 긴 명칭은 **바꾸기 규칙**으로 따로 넣어야 고쳐집니다.

예전에는 이름·용어 목록을 Whisper 인식 힌트(프롬프트)로도 넣을 수 있었지만 **없앴습니다.**
힌트는 224토큰(한글 약 80~100자)까지만 들어가 수백 개 용어 중 일부만 담을 수 있고, 목록을 주면 Whisper가
"사업자의 사업자의 …"처럼 같은 말을 되풀이하거나 "○○○ 기자가 보도합니다" 같은 없는 문장을 지어내는 일이 잦았습니다.
실제 회의 녹음 90초로 비교하니 목록을 넣으면 기준 문장과 차이 17.6%, 빼고 직전 문장만 힌트로 주면 11.7%였습니다.
지금은 인식 힌트로 **직전에 확정된 문장만** 줍니다.

사전이 커져도 안전하도록 세 가지 장치를 두었습니다.
- 긴 규칙을 먼저 적용합니다(짧은 규칙이 긴 이름을 깨뜨리지 않게).
- 4글자 이하 짧은 규칙은 앞 글자가 한글이면 건너뜁니다. ("심 사"→"심사" 규칙이 "핵심 사업"을 망가뜨리지 않습니다)
- 짧은 낱말일수록 더 비슷해야 고칩니다. 조사는 떼고 비교한 뒤 다시 붙입니다.
  ("예산을"은 "예산안"으로 바뀌지 않고, "예산결산특위원회를"은 "예산결산특별위원회를"로 고쳐집니다)

실제 도의회 영상에서 자주 나오는 오인식 예: `노고→노구`, `취약 지역→최악 지역`, `재석의원→재석위원`,
`주민참여형→중인참여형`, `RE100→알리백`. 이런 말을 용어집에 넣어 두면 대부분 잡힙니다.

### 2-5. 녹음과 듣기 (검수용)

받아쓰기를 시작하면 소리도 함께 녹음됩니다(16kHz mono WAV, `data/sessions/<회의>/audio.wav`).
'저장된 파일'로 올린 원본은 받아쓰기가 끝나면 지웁니다(녹음은 위 audio.wav 로 남음). 받아쓰는 도중 프로그램이 꺼져
남은 원본은 다음에 켤 때 지웁니다.

**받아쓰기 탭과 기록·요약 탭 모두 재생기가 있습니다.** (기본 1.5배속)
받아쓰는 중에는 녹음 중인 소리와 섞이지 않도록 재생을 막습니다.

| 조작 | 하는 일 |
|---|---|
| 문장 클릭 | 그 대목부터 이어서 재생 |
| 스페이스바 | 재생 / 멈춤 |
| ← → | 3초 뒤로 / 앞으로 |
| Shift + ← → | 이전 문장 / 다음 문장으로 |
| 속도 | 0.5배 ~ 2배 (받아쓰기는 0.75배가 편합니다) |
| 따라가기 | 재생 위치를 따라 문장이 자동으로 따라 내려갑니다 |
| 한 문장 반복 | 잘 안 들리는 문장을 반복해서 듣습니다 |
| 음성 파일 | 회의 녹음 전체를 내려받습니다 |

기본 배속은 1.5배, '한 문장 반복'은 꺼져 있습니다.

재생 중인 문장은 파란 줄로 표시됩니다. 들으면서 바로 '수정'으로 글자를 고칠 수 있습니다.
(글을 고치는 중에는 단축키가 동작하지 않으니 안심하고 타이핑하세요)

### 2-6. 얼굴 등록

충청남도의회는 한 줄로 끝납니다. 누리집에서 의원 이름과 공식 사진을 받아 얼굴까지 등록합니다.

```bash
.venv\Scripts\python.exe -m scripts.import_members --council chungnam
```

다른 의회나 직접 모은 사진:

```bash
.venv\Scripts\python.exe -m scripts.import_members --list-url https://council.xxx.go.kr/
.venv\Scripts\python.exe -m scripts.import_members --photos "C:\사진폴더"   # 파일명이 곧 이름
```

공식 사진만으로도 실제 중계 화면에서 잘 맞지만(검증: 유사도 0.55~0.79, 판정선 0.36),
중계 화면에서 한두 장 더 등록하면 더 좋아집니다.

**받아쓰기 탭 오른쪽에서 바로 등록합니다.**
1. '화면 감시'를 켭니다 (미리보기에 지금 보고 있는 화면이 뜹니다)
2. 발언자가 크게 보일 때 **[지금 화면에 나오는 얼굴 캡처]**
3. 잡힌 얼굴에 이름을 적고 등록

'화면 감시'와 녹취록 위 화자 구분의 **'얼굴' 스위치는 함께 움직입니다.** 감시를 켜면 '얼굴'이 켜지고,
끄면 '얼굴'도 꺼집니다(반대로 '얼굴'을 눌러도 감시가 따라 바뀝니다). 감시를 끄면 미리보기는 처음처럼 빈 칸으로 돌아갑니다.

등록된 사람 목록과 삭제는 **설정 탭** 아래쪽에 있습니다. 사진이 없는 사람은 이름 첫 글자로 표시됩니다.
명부(`data/members.json`, 이름·직함)는 공개판에서는 비어 있습니다. 각 기관에서 등록하세요.
얼굴 특징과 목소리 성문(`data/faces/`)은 이 PC에만 둡니다.

### 2-7. 화자는 이렇게 가립니다

1. **얼굴** — 중계 화면을 1초에 두 번 캡처해서, 가장 크게 잡힌 얼굴을 지금 발언 중인 사람으로 봅니다.
   (의회 중계는 발언자를 클로즈업하므로 잘 맞습니다)
2. **목소리** — 얼굴로 확인된 구간의 목소리를 그 의원의 성문으로 자동 저장합니다.
   그래서 회의가 진행될수록, 카메라가 전경을 비추는 동안에도 목소리만으로 화자를 맞힙니다.
   잘못 배운 성문은 이후 회의를 계속 망치므로, **얼굴 유사도 0.45 이상 + 구간의 70% 이상 그 사람이
   화면에 있었을 때 + 3초 이상 발언**일 때만 학습합니다.
   (중계 화면이 '듣고 있는 다른 의원'을 비추는 동안 의장이 말하는 경우가 흔하기 때문입니다)
   화자가 엉뚱하게 붙기 시작하면 **설정 탭 → 학습된 목소리 전체 초기화**로 지우면 됩니다.
3. **직접 지정하면 목소리를 배웁니다** — 문장의 '화자' 버튼을 눌러 이름을 정하면,
   그 발언의 성문을 학습합니다. 같은 회의 안에서 아직 이름이 없던 발언 중
   목소리가 같은 것들도 한꺼번에 바뀌고, 이후 들어오는 발언도 자동으로 그 이름이 붙습니다.
   (이름은 곧바로 바뀌고, 같은 목소리를 찾는 일은 뒤에서 해 끝나는 대로 알려 줍니다)
4. **맥락 (자기소개·사회자 지명, AI 없이)** — 충청남도의회 제371회 임시회 회의록 8건(발언 3,140개)을 분석해 만든
   규칙으로 알아봅니다. (표시: `맥락`) 의원이 발언하기 직전 사회자 말의 87%에 그 의원 이름이 나왔습니다.
   - 사회자 지명: "김철수 위원님 질의해 주시기 바랍니다"(가장 많음), "… 질의하여 주시기 바랍니다 / 질의해 주십시오 /
     질의하시기 바랍니다 / 질의하십시오", "최지은 부위원장님 추가 질의해 주시기 바랍니다",
     "이훈 의원님 나오셔서 발언하여 주시기 바랍니다", "박민수 위원님은 나오셔서 제안설명해 주시기 바랍니다",
     "김철수 위원님."(이름만 짧게), "최병묵 행정국장님 나오셔서 답변해 주시기 바랍니다"
     → 사회자와 다른 목소리가 나오면 그때부터 그 사람으로, 목소리가 다시 바뀌면 끝.
     음성인식이 "김철수 위원님" / "질의해 주시기 바랍니다"를 두 문장으로 나눠도 알아봅니다.
   - 자기소개: "천안 출신 박민수 의원입니다", "교육위원회 최지은 의원입니다", "서산 김철수입니다",
     "행정국장 최병묵입니다" → 그 문장과 같은 목소리로 이어지는 앞뒤 문장을 그 사람으로.
   - 지명이 아닌 말은 거릅니다: "김철수 위원님 수고하셨습니다", "김철수 위원님께서 질의하신 부분에 답변해 주시기 바랍니다",
     "국장님께 질의하실지 말씀해 주시기 바랍니다", 간부 소개("이승열 기획조정실장 직무대리입니다"), "다음 질의자는 ○○○ 위원입니다".
   - **사람 이름이 아닌 말은 화자로 잡지 않습니다.** "김철수 국회의원 공약사항입니다"의 '공약사항'처럼
     명부에 없는 낱말은 성씨로 시작하는 2~3글자(두 글자 성씨면 4글자)인지, '사항·계획·사업·결과' 같은
     흔한 회의 낱말로 끝나지 않는지 보고 이름일 때만 씁니다.
   - 이름은 **등록된 의원 명부와 자모로 비교**해 가장 가까운 사람으로 맞춥니다(홍길둥 → 홍길동, 이영히 → 이영희).
     의원·위원 직함 앞의 이름은 명부에 있을 때만 쓰고, 집행부 직함 앞의 이름은 명부와 똑같을 때만 명부 이름으로 봅니다
     (김재한 수석전문위원을 비슷한 의원 '김재훈'로 바꾸지 않도록). 명부에 없는 집행부 간부는 들린 이름으로 새로 등록합니다.
   - 회의록 시험 결과: 사회자 지명 183건 맞음/3건 틀림(예전 규칙 123/38), 자기소개 170건 맞음/1건 틀림(예전 28/0).
     의원·간부 발언 10,638문장 중 지명으로 잘못 읽힌 문장 0.
   - Codex 로그인이 있으면 규칙으로 못 알아본 지명 말투의 문장만 Codex에게 한 번 더 묻습니다. 없으면 Claude Code 로그인을 사용합니다.
   이렇게 확인된 목소리는 성문으로도 배웁니다. 녹취록 위 '맥락' 스위치나 설정 탭 → 화자 구분에서 끌 수 있습니다.
5. **이어짐 판단** — 한 사람이 여러 문장을 이어서 말하면 하나의 화자로 묶습니다.
6. 그래도 모르면 `화자 1`, `화자 2`로 두고, 나중에 이름을 바꿔 주면 됩니다.
7. **잘못 붙은 이름 지우기** — 문장의 '화자' 버튼 → 아래쪽 **이 문장 이름 지우기** 또는
   **이 회의의 '○○○' 모두 지우기**. 지운 문장은 `화자 1`, `화자 2`처럼 번호로 보이고,
   얼굴·목소리·맥락 스위치를 다시 켜도 그 이름이 다시 붙지 않습니다.
   목소리로 잘못 붙었던 이름이면 그 사람의 성문 중 이 목소리와 닮은 것도 지워, 다음 회의에서 같은 실수를 줄입니다.

**방법끼리 판단이 엇갈릴 때** — 한 가지 방법만 고르지 않고, 방법마다 얼마나 확실한지(유사도, 구간 내내 얼굴이 보였는지 등)를
점수로 매겨 사람별로 합칩니다. 여러 방법이 같은 사람을 가리키면 확신이 커집니다.
예) 목소리는 의장인데 화면에는 듣고 있는 의원 → 목소리가 확실하면 의장 /
사회자가 이영희 의원을 지명했는데 얼굴·목소리가 모두 다른 사람 → 그 사람.
앞뒤 문장이 같은 사람인데 가운데 짧은 문장만 근거 약하게 다른 사람이면 앞뒤를 따릅니다.
판단이 엇갈린 문장은 표시에 `≠`가 붙고, 마우스를 올리면 방법별 판단이 보입니다.

**방법별로 켜고 끄기** — 녹취록 위 `화자 구분: 얼굴 · 목소리 · 맥락` 스위치로 방법마다 켜고 끌 수 있습니다.
녹취 중에도, 끝난 뒤 기록·요약 탭에서도 누르는 즉시 녹취록 전체의 화자가 다시 정해집니다.
(문장마다 방법별 결과를 따로 저장해 두기 때문입니다. 직접 지정한 화자는 바뀌지 않습니다)
- 켜 두지 않았던 **목소리·맥락**은 나중에 켜면 녹음 파일과 AI로 지나간 부분을 채웁니다.
- **얼굴**은 녹취하는 동안의 화면만 볼 수 있어, 그때 꺼져 있던 구간은 나중에 채울 수 없습니다.
- 받아쓰기 탭의 스위치는 다음 회의의 기본값(설정 탭 → 화자 구분)도 함께 바꿉니다.

화면 감시 영역은 받아쓰기 탭 '화면 속 발언자'의 **드래그로 지정**을 눌러, 지금 화면을 찍은 그림 위에서 끌어 고를 수 있습니다. (설정 탭에서 좌표로 넣어도 됩니다)
중계 창만 지정하면 다른 창의 얼굴에 헷갈리지 않습니다.

## 4. 성능과 CPU 사용량 (이 PC 실측: Ryzen 7 8845HS, 16GB, GPU 가속 없음)

### 성능 모드 (설정 탭에서 고릅니다)

| 모드 | 미리보기 | 언제 쓰나 |
|---|---|---|
| 보통 (기본) | 인식이 끝나는 대로 계속 갱신 (이 PC는 약 6초마다, 빠른 PC는 2초마다) | 받아쓰는 걸 지켜볼 때 |

'보통'은 인식이 끝나면 곧바로 다음 인식을 합니다. 인식 한 번은 소리 길이와 관계없이 30초 창을 통째로 처리해

다른 프로그램이 느려지지 않게 하는 일은 '다른 프로그램에 CPU 양보'(낮은 우선순위)가 맡습니다.
예전의 '빠름'은 이것과 같아 '보통'으로 합쳤습니다. 인식 품질은 두 모드가 같습니다. 차이는 '같은 소리를 몇 번 다시 인식하느냐'뿐입니다.
(아래 CPU 수치는 예전 세 모드 기준 실측입니다)

### 왜 예전엔 CPU가 98%였나

기본 스레드 수가 논리 코어 수(16)에 맞춰져 있었습니다. 실측해 보면

| 스레드 | 12초 버퍼 인식 시간 |
|---|---|
| 3 | 7.28초 |
| 6 | 4.60초 |
| 12 | 4.08초 |

스레드를 두 배로 늘려도 12%밖에 빨라지지 않습니다. 그래서 기본값을 **물리 코어 − 2**(이 PC에서 6)로
바꾸고, 프로세스 우선순위도 낮췄습니다. 다른 창을 쓰는 데 지장이 없습니다.

### 모델 선택 (실측)

| 모델 | 12초 버퍼 | 1분 배치 | 품질 |
|---|---|---|---|
| small | 2.70초 | 5.5초 | 이름을 자주 틀림 (수해→수혜 등) — **없앰** |
| medium | 8.08초 | 16.5초 | **turbo보다 느리고 부정확** — **없앰** |
| large-v3-turbo | 4.32초 | 14.7초 | 가장 정확. 기본값 |

2026-09-30 실제 회의 녹음(90초)을 실시간처럼 흘려 넣어 다시 비교한 결과, small 은 앞 30초를 통째로 놓치거나
힌트의 이름만 되풀이했고(기준 문장과 41~100% 차이), medium 은 turbo보다 4초쯤 빠를 뿐 틀리는 비율이 두 배(20%)였습니다.
그래서 기본 배포 모델은 large-v3-turbo 하나만 둡니다. 예전 설정의 small·medium·large-v3 등은 자동으로 large-v3-turbo로 바뀝니다. 다른 CTranslate2 모델이 이미 있다면 설정 탭에서 그 폴더를 지정할 수 있습니다.

파일 받아쓰기는 실시간의 약 1.8배 속도(2시간 회의 ≈ 1시간 10분), 실시간 지연은 4~8초, 메모리는 약 2.5GB입니다.

### GPU는 왜 못 쓰나

이 PC의 Radeon 780M(내장 그래픽)은 아래 이유로 실용적인 경로가 없습니다.

| 방법 | 가능 여부 |
|---|---|
| CTranslate2(현재 엔진) GPU | **NVIDIA CUDA 전용**. AMD 미지원 |
| ONNX Runtime DirectML | 패키지는 있지만, Whisper 디코딩 루프를 직접 구현해야 함(대공사) |
| sherpa-onnx | provider가 cpu/cuda/coreml뿐 |
| whisper.cpp + Vulkan | 기술적으로 가능하나, 최신 버전은 Windows 실행파일을 더 이상 배포하지 않아 직접 빌드해야 함 |

**NVIDIA 그래픽카드가 있는 PC**라면 설정에서 장치를 `CUDA`로 바꾸기만 하면 5~10배 빨라집니다.
(별도 작업 필요 없음)

## 5. 설치 파일 만들기 (다른 PC에 나눠 주기)

```bash
.venv\Scripts\python.exe -m scripts.build_exe                # 정식판: 모델 + 명부(이름·직함), 얼굴·성문 없음 → 말결_설치.exe
.venv\Scripts\python.exe -m scripts.build_exe --no-models --model-url https://…/조각을올린곳/
                                                             # 경량판: 모델 없이, 설치할 때 받음 → 말결_설치_경량.exe

```

`배포\` 폴더에 설치 파일 하나가 만들어집니다. **이 파일만 주면 됩니다.** 세 종류는 이름이 달라 서로 덮어쓰지 않습니다.
`배포\말결…` 폴더는 설치 파일을 만드는 작업 공간이니, 시험은 설치 파일로 설치한 뒤에 해 주세요
(그 폴더에서 직접 실행하면 바뀐 꾸러미가 다음 설치 파일에 섞입니다).

받는 사람은 두 번 누르기만 하면 됩니다(1-1). 다시 실행하면 '프로그램만 덮어쓰기 / 전부 새로 설치'를 고를 수 있어,
**회의 기록과 설정을 지키면서 프로그램만 갱신**할 수 있습니다.
- 프로그램만 덮어쓸 때 그 PC의 용어사전·설정·`data/.env`의 API 키·명부(배운 얼굴·목소리)는 그대로 두고, 새 명부에만 있는 사람만 더합니다.
- 예전 이름('회의 실시간 자막')으로 설치했던 PC는 덮어쓸 때 옛 바로가기와 실행 파일을 지우고 새 이름으로 만듭니다.
- **제거**: Windows 설정 → 앱 → 설치된 앱(또는 제어판 → 프로그램 제거)에 '말결'로 올라갑니다. [제거]를 누르면
  회의 기록(녹음·녹취록)·설정·등록된 얼굴/목소리도 지울지 묻고(기본: 남겨 둠), 바로가기와 프로그램 파일을 지웁니다.
  남겨 두면 설치 폴더의 data 만 남고, 다시 설치하면 그대로 이어서 씁니다. (scripts/uninstall_main.py)
- 설치 전에 남은 공간을 확인합니다. 관리자 권한은 필요 없습니다.
- 설치 파일에는 정해진 파일만 담깁니다. 꾸러미 폴더에서 프로그램을 실행해 생긴 녹음·설정·실행 기록은 들어가지 않습니다.

| 정식판에 담기는 것 | 크기 |
|---|---|
| 파이썬 실행기 + 꾸러미 | 약 480MB (쓰지 않는 꾸러미 정리) |

### 경량판이 모델을 받는 방법

경량판은 원본(1.6GB)을 받아 PC에서 줄이는 대신, **미리 줄여 둔 모델 묶음(약 0.9GB)** 을 받습니다.
GitLab 패키지 저장소는 파일 하나의 크기 제한이 있어 묶음을 45MB 조각으로 나눠 올려 두었고,
설치 프로그램이 조각을 차례로 받아 이어 붙입니다(이 PC 기준 약 50초).

- 조각마다, 그리고 이어 붙인 전체 파일의 **지문(SHA-256)** 을 맞춰 봅니다. 손상되거나 다른 파일이면 쓰지 않습니다.
- 그 주소에 연결되지 않거나 지문이 다르면, 원래 방법(원본을 받아 PC에서 줄이기)으로 이어서 받습니다.
- 인터넷이 아예 안 되면 설치는 끝내고, 나중에 다시 실행해 '프로그램만 새로 덮어쓰기'를 고르면 모델만 이어서 받는다고 안내합니다.
- 받을 주소는 설치 파일을 만들 때 넣습니다(`data/models_source.json`). 지금 주소:
  `https://gitlab.aigov.go.kr/api/v4/projects/soyoung776%2Flivecaption/packages/generic/livecaption-models/1.0.0/`
  (공개 프로젝트라 로그인 없이 받을 수 있습니다)

음성인식 모델을 바꾸면 묶음을 다시 만들어 올려야 합니다.

```bash
.venv\Scripts\python.exe -m scripts.download_models --make-bundle 배포\livecaption-models-large-v3-turbo.zip --split 45
```

만들어진 `….zip.001` ~ `….zip.021` 을 패키지 저장소 `livecaption-models/<버전>/` 에 올린 뒤(GitLab 토큰 필요),
그 주소를 `--model-url` 로 넣어 경량판을 다시 만듭니다. 묶음 원본(`….zip`)과 조각은 지문 계산에 쓰이니 `배포\` 에 남겨 두세요.

알아둘 점
- 백신이 처음 보는 exe를 막을 수 있습니다. 사내 배포 전에 한 대에서 확인해 보세요.
- 설치 경로에 한글이 있으면 얼굴 인식이 동작하지 않을 수 있습니다(OpenCV 제약). 설치 프로그램이 경고합니다.
- 폴더 방식으로 나눠 주려면 `scripts.build_package` 도 그대로 쓸 수 있습니다.

## 6. 릴리스와 새 버전 알림

### 릴리스 올리기 (GitLab)

1. `app/version.py` 의 `VERSION` 을 올립니다 (예: `1.0.0` → `1.1.0`)
2. 경량 설치 파일을 만듭니다 (5장)

   - 경량 설치 파일을 패키지 저장소(`livecaption-installer/<버전>/`)에 올립니다.
   - 같은 버전의 릴리스(태그 `v1.1.0`)를 만들어 받는 링크와 설명을 붙입니다.

   (`배포\` 폴더는 저장소에 올라가지 않으니 토큰을 넣어도 됩니다. 다 쓰면 토큰을 지우고 GitLab에서 폐기하세요)

## 7. Lightning-SimulWhisper 와의 관계

이 프로그램은 [Lightning-SimulWhisper](https://github.com/altalt-org/Lightning-SimulWhisper)의
**구조**(오디오 청크 입력 → 반복 처리 → 확정/미확정 분리, 용어 고정 프롬프트)를 참고했지만,
그 저장소의 코드를 담고 있지는 않습니다. 이유는 두 가지입니다.

1. 그 구현은 **Apple Silicon 전용**입니다(MLX + CoreML). Windows/AMD에서는 실행되지 않습니다.
   그래서 같은 역할을 하는 faster-whisper(MIT, CTranslate2)로 엔진을 바꿨습니다.
2. 그 저장소는 **PolyForm Noncommercial**(비상업용) 라이선스입니다.
   공공기관 업무는 허용 범위지만, 영리 목적 녹취 업무에는 별도 확인이 필요합니다.

Mac에서 쓰고 싶다면 그 저장소를 직접 클론한 뒤 설정의 `asr.simulwhisper_path` 에 경로를 넣으면
선택 엔진(AlignAtt 정책)으로 붙습니다. 그 경우에만 해당 라이선스가 적용됩니다.

확정 방식은 whisper_streaming 계열에서 쓰는 **LocalAgreement-2** 입니다.
연속된 두 번의 인식에서 같은 자리에 같은 단어가 나오면 그때 확정하므로, 확정된 글자는 다시 바뀌지 않습니다.

## 9. 기관 내부망(업무포털)에 배포하려면

먼저 분명히 해 둘 점이 있습니다. **지금 구조를 그대로 서버에 올리면 다른 사람이 쓸 수 없습니다.**

| 기능 | 서버에 올렸을 때 실제로 일어나는 일 |
|---|---|
| PC 소리 캡처 | **서버 컴퓨터의** 스피커 소리를 녹음합니다. 사용자 PC 소리가 아닙니다. |
| 화면 얼굴 인식 | **서버 컴퓨터의** 화면을 봅니다. 사용자 화면이 아닙니다. |
| 받아쓰기 세션 | 프로그램 전체에 하나뿐입니다. A가 시작하면 B도 같은 화면을 봅니다. |
| 녹취록·명부·용어집 | 전 사용자 공용입니다. 남의 회의 내용이 서로 보입니다. |
| 성능 | 한 사람이 쓰면 CPU가 거의 다 찹니다. 동시 2명이면 실시간을 못 따라갑니다. |

브라우저는 보안상 웹서버에 "내 PC 소리"를 그냥 넘겨주지 않습니다.
그래서 배포 방법은 아래 넷 중에서 고르게 됩니다.

### 가. 각 PC에 설치해서 쓰기 (지금 구조 그대로, 권장)
포털에는 설치 파일과 사용 안내만 올리고, 프로그램은 각자 PC에서 돌립니다.
- 추가 개발 거의 없음. 지금 바로 가능 (5장의 설치 파일).
- 회의 음성은 기관 밖으로 나가지 않습니다. 요약과 일부 화자 지명 판별에는 녹취 텍스트가 외부 AI로 전송됩니다.
- 단점: PC마다 1.5GB 남짓 공간과 설치 절차가 필요합니다.

### 나. 서버에는 "파일·주소 받아쓰기"만 올리기
실시간 캡처는 빼고, 사용자가 녹음 파일이나 중계 주소를 올리면 서버가 받아써 주는 형태.
- 필요한 작업: 사용자별 로그인(포털 계정 연동), 사용자별 녹취록 분리, 작업 대기열(동시 처리 제한), 진행률 표시.
- 중간 규모 개발(1~2주). 서버 CPU가 넉넉하거나 GPU가 있으면 좋습니다.

### 다. 브라우저에서 소리를 받아 서버로 보내기
사용자가 브라우저에서 "탭 오디오 공유"를 허용하면, 그 소리를 서버로 흘려보내 받아씁니다.
화면도 같이 공유하면 얼굴 인식까지 서버에서 할 수 있습니다.
- 가장 포털다운 형태이고, 각자 자기 회의를 실시간으로 받아쓸 수 있습니다.
- 필요한 작업: 브라우저 오디오 캡처·전송, 다중 세션 처리, 서버 자원 관리.
- 큰 개발(2~4주)이고 **동시 사용자 수만큼 CPU/GPU가 필요**합니다.
  (large-v3-turbo 기준 동시 1명당 CPU 8코어 또는 GPU 1장의 일부)

### 라. 섞어 쓰기 (현실적인 추천)
실시간 녹취는 담당자 PC에서(가), 완성된 녹취록은 포털에 모아 함께 보기.
- 포털 쪽은 "녹취록 열람·검색·내보내기" 전용이라 가볍고 안전합니다.

### 어느 쪽이든 배포 전에 반드시

1. **인증 기능이 없습니다.** 이 프로그램은 각자 PC에서 혼자 쓰는 것을 전제로 하며,
   사내망에 열면 접속한 누구나 모든 기능을 씁니다. 포털 배포라면 계정 연동(SSO)을 따로 만들어야 합니다.
2. `data/settings.json` 의 `server.host` 를 `0.0.0.0` 으로 바꿔야 외부 접속이 됩니다.
   **열면 접속한 누구나 녹취록·얼굴 정보·API 키 설정을 볼 수 있습니다.**
3. 개인정보를 확인하세요. 이 프로그램은 **얼굴 특징과 목소리 성문**을 저장합니다.
   생체정보에 해당할 수 있어, 기관 개인정보 담당자와 보관 기간·접근 권한·파기 절차를 정해야 합니다.
4. AI 요약은 녹취록을 외부 AI로 보냅니다. 내부망 규정상 문제가 되면 AI 요약을 사용하지 마세요.
   (키가 없으면 그 기능만 동작하지 않습니다).
5. HTTPS와 접근 통제는 앞단(리버스 프록시)에서 거는 것을 권합니다.

## 10. 알아둘 점

- 경로에 한글이 있어도 동작하지만(OpenCV 제약은 자동 우회), 영문 경로가 더 안전합니다.
- 회의가 길면 녹음 파일이 커집니다. 16kHz mono 기준 **1시간에 약 115MB**.
  녹음이 필요 없으면 `data/settings.json` 의 `audio.record` 를 `false` 로 두세요(듣기 기능도 함께 꺼집니다).
- **받아쓰는 중에 창을 닫아도 회의는 저장됩니다.** 창은 바로 사라지지만, 마지막 문장까지 정리해 저장하는 동안
  (몇 초~수십 초) 작업 관리자에 프로그램이 남아 있다가 스스로 끝납니다. 그동안 강제로 끄지 마세요.
- 프로그램을 두 개 띄워도 설정이 서로 덮어써지지 않도록, 설정 파일이 바뀌면 다시 읽습니다.
- Whisper는 무음·박수·잡음 구간에서 없는 말을 지어낼 때가 있습니다.
  무음 제거, 반복 구절 탐지, 발화 길이 대비 글자수 검사로 걸러내지만 완벽하지는 않습니다.
  공식 녹취록으로 쓸 때는 반드시 소리를 들으며 검수하세요. (문장 클릭 재생이 그 용도입니다)
- 얼굴 인식은 화면에 얼굴이 보일 때만 동작합니다. 자료 화면이 길게 나오면 목소리로 판단합니다.
